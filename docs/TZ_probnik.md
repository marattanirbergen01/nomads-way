# ТЗ окну «Код»: рабочий пробник ЕНТ на банке вопросов школы

Дата: 2026-10-13, последняя правка 2026-10-14 (картинки контекстов, два режима, тест по сезону). Решение — `docs/DECISIONS.md`, запись «Пробник ЕНТ берёт вопросы из банка школы».

## Что есть сейчас
- `app/lib/features/train/mock_test_screen.dart` — «Сынақ ҰБТ»: `QuizRunner.composeFinal(bank, single: 10, context: 10)`
  берёт случайные вопросы **только из серий** (сейчас это одна s1e01, 29 вопросов).
- Контекстные вопросы берутся вразнобой: 10 случайных вопросов из разных сцен, без текста контекста.
  На ЕНТ так не бывает.
- Варианты ответа уже перемешиваются в `QuizRunner` (`_shuffled`). Это нужно сохранить и для банка.

## Что появилось в контенте
`content/bank/school_tests.yaml` — банк пробника, формат описан в `docs/CONTENT_FORMAT.md`,
раздел «content/bank». Сводка:

| | всего | годны для пробника (без `check` и `image_missing`) |
|---|---|---|
| вопросы с одним ответом (`single`) | 2 350 | 2 281 |
| контекстные вопросы (`context`) | 364 | — |
| контексты | 72 | 72, у каждого ≥ 5 годных вопросов |
| — из них карта/схема (только картинка) | 16 | |
| — текст с картинкой | 1 | |
| вопросы с одним ответом и своей картинкой | 14 | |

Тексты только на казахском. Источник — `school_tests_2026` в `content/sources/registry.yaml`.

**Картинки** (карты и схемы из исходных файлов) лежат в `content/bank/media/*.jpg` (23 файла, 1,1 МБ, до 1600 px).
В банке путь записан относительно `content/bank/`: `image: media/m_ig_6365.jpg`.
Контексты бывают трёх видов (всего 72):

| вид | сколько | что в банке |
|---|---|---|
| текст (документ, биография) | 55 | `text` |
| карта или схема | 16 | `image` + подпись `caption`, текста нет |
| текст и картинка | 1 | `text` + `image` (депутаты Думы с фотографиями) |

Экран должен уметь показать все три вида. Вопросы к карте без самой карты не решаются.
У 14 вопросов с одним ответом тоже есть своя `image`.

## Что сделать

### 1. Компилятор (`tools/bin/compile.dart`)
1. Читать `content/bank/*.yaml`, класть в сборку (`build/bank.json` или в common-бандл — на ваше усмотрение;
   YAML 1,4 МБ, в JSON + gzip будет заметно меньше).
2. Проверки (ошибка — сборка падает):
   - `id` вопросов и контекстов уникальны, в том числе против вопросов серий;
   - `answer` — индекс внутри `options`; вариантов 3–6; `stem.kk` и каждый `options[].kk` не пустые;
   - у `format: context` есть `context`, он существует, и вопрос стоит в его `questions`; у `single` поля `context` нет;
   - `source` банка есть в `registry.yaml`;
   - у контекста есть `text` или `image` (или оба); каждый файл из `image` существует в `content/bank/media/`.
3. **Картинки банка обязательно попадают в сборку** (`content/bank/media/` → туда же, куда сам банк,
   с сохранением имён). Без них 16 контекстов и 14 вопросов нерешаемы.
4. К банку **не применять** правила серий: `fact` ↔ `covers`, обязательный `ru`, `explain`, «без перевода en».
5. В отчёт `--check` строкой: сколько вопросов и контекстов в банке, сколько годны для пробника.

### 2. Сборка варианта пробника (новая функция рядом с `composeFinal`, например `composeMock`)
Структура как на ЕНТ по спецификации НЦТ: **20 заданий**.
1. **Задания 1–10 — один ответ.** 10 случайных вопросов `format: single` из годных.
   Не больше 2 вопросов на одну тему ЕНТ (`topic`), чтобы вариант был по всему курсу.
2. **Задания 11–20 — два контекста по 5 вопросов.**
   - Случайно выбрать 2 **разных** контекста, у которых ≥ 5 годных вопросов.
   - Из каждого взять 5 годных вопросов (если годных больше 5 — случайные 5).
   - **Порядок 5 вопросов внутри контекста перемешать**, но структура сохраняется: блок 11–15 — только
     вопросы контекста 1, блок 16–20 — только вопросы контекста 2. Вопрос никогда не отрывается от своего текста.
   - Какой контекст будет первым — тоже случайно.
   - У контекста может быть больше 5 вопросов (сейчас один — схема реформ 1880–90-х, 9 вопросов):
     из него берутся **случайные 5**, как из любого другого.
3. **Годный вопрос** = нет `check: true` и нет `image_missing: true`. Остальные в пробник не попадают никогда.
4. **Варианты ответа перемешиваются у каждого вопроса** при каждом показе, буквы A–D
   (A–E, A–F) назначаются заново после перемешивания. Правильность проверяется по самому варианту, не по букве.
   Исключение: `shuffle: false` — порядок как в файле.
   (Важно: в исходном тесте «Алаш» правильный ответ почти всегда под A — без перемешивания это подсказка.)
5. Желательно: не повторять вопросы из последних 3 пробников ученика, пока в пуле хватает других.
6. Функция принимает `Random`, чтобы тесты были детерминированными.

### 2а. Второй режим — «Жылдам жаттығу» (быстрая тренировка), функция `composeQuick`
Пробник «Сынақ ҰБТ» остаётся точной копией ЕНТ (10 + 5 + 5). Рядом — отдельный режим для тренировки
одиночных вопросов:
1. **Задания 1–15 — один ответ**, 15 случайных годных `single`; не больше 2 на одну тему ЕНТ.
2. **Задания 16–20 — один контекст**, 5 его годных вопросов (если больше 5 — случайные 5), порядок
   внутри блока случайный.
3. Всё остальное как в пробнике: те же правила годности, перемешивание вариантов, `Random` на входе.
4. Результат сохранять отдельно от пробника (`kind: 'quick'`), чтобы «последний пробник» на «Жаттығу»
   показывал только настоящие пробники.

### 3. Экран пробника
1. Перед заданиями 11–15 и 16–20 показывать контекст: текст, **картинку** или оба. Пока ученик отвечает
   на 5 вопросов блока, контекст должен быть доступен (над вопросом, раскрывающимся блоком или кнопкой
   «Мәтін» / «Карта» — как удобнее в дизайне).
   **Картинку показывать обязательно**, с увеличением по нажатию (карты мелкие, подписи читаются только
   при зуме). Подпись `caption` — под картинкой.
   У вопроса с одним ответом и `image` — картинка над вопросом, тоже с увеличением.
2. Номер задания (1–20) сквозной; у контекстных видно «Мәтін 1» / «Мәтін 2».
3. После ответа: верно/неверно и правильный вариант. Объяснений (`explain`) у банка нет — не показывать пустой блок.
4. Итог: X из 20, отдельно 1–10 и 11–20, список ошибок с правильными ответами.
5. Пробник сохранять как сейчас (`recordAsMock: true`), быструю тренировку — с `kind: 'quick'`. В `Attempt.fact` у вопросов банка факта нет — писать
   `ent.<topic>` (или пусто), но **не засчитывать их в прогресс фактов серий** на «Дайындық».
6. Язык интерфейса ru: вопросы банка только kk. Показывать их на казахском и над пробником строку
   «Вопросы пробника пока только на казахском».
7. На «Жаттығу» две карточки: «Сынақ ҰБТ» (10 + 5 + 5) и «Жылдам жаттығу» (15 + 5). Кнопка «Бастау» у пробника
   активна при ≥ 10 годных single и ≥ 2 контекстах, у быстрой тренировки — при ≥ 15 single и ≥ 1 контексте.
8. Экран один и тот же для обоих режимов; у быстрой тренировки в итоге: X из 20, отдельно 1–15 и 16–20.

### 4. Потом (не в этой задаче)
- Тест по сезону: **без контекста**, только вопросы с одним ответом из этого сезона (`season == N`),
  20 случайных штук. Ограничения «не больше 2 на тему» здесь **нет**: цель — повторить именно темы сезона.
  Остальные правила (годность, перемешивание вариантов) — общие.
- Вопросы серий добавить в общий пул пробника.

## Как принять
Юнит-тесты на `composeMock` с фиксированным `Random`:
- ровно 20 вопросов; первые 10 — `single`, без повторов;
- 11–15 — один контекст, 16–20 — другой, ни один вопрос не из чужого контекста;
- из контекста с 9 вопросами берутся ровно 5, при разных seed — разные пятёрки;
- при разных seed порядок внутри блока разный, состав блока — из своего контекста;
- `check` и `image_missing` не попадают ни при каком seed (прогнать 1000 seed);
- после перемешивания вариантов правильный вариант тот же по тексту; `shuffle: false` — порядок исходный;
- не больше 2 вопросов на одну тему в 1–10;
- контексты-карты участвуют в выборе наравне с текстовыми.

Юнит-тесты на `composeQuick`: ровно 20; первые 15 — `single` без повторов, не больше 2 на тему; 16–20 — один
контекст; `check`/`image_missing` не попадают; варианты перемешаны с сохранением правильного.

Вручную: пройти пробник в приложении, убедиться, что текст или картинка контекста видны на всех пяти
его вопросах, а карта увеличивается и читается на телефоне.
